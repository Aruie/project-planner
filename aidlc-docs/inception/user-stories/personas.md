# Personas

## P-ADMIN — 프로젝트 관리자 및 산출물 작성자

### 개요
- **유형**: MVP의 유일한 실제 제품 사용자
- **인증 상태**: 임시 자동 로그인
- **권한**: 프로젝트, 산출물, Draft, 확정 버전, 첨부 이미지, 내보내기, 추적성, AI 작업공간의 모든 기능을 수행
- **작업 컨텍스트**: 반드시 프로젝트를 생성하거나 선택한 뒤 그 프로젝트 안에서 모든 메뉴를 사용

### 목표
1. 프로젝트별 개발 산출물을 한 곳에서 구조적으로 관리한다.
2. Markdown 중심으로 빠르게 작성하고, 정형 산출물은 Excel/DOCX로 공유한다.
3. Draft와 확정 버전을 구분하여 무엇이 언제 바뀌었는지 명확히 확인한다.
4. RFP와 후속 지시를 대화식으로 보완해 요구사항정의서 초안을 만들되, 검토 전에는 정식 저장하지 않는다.
5. 사용자스토리·요구사항·테스트케이스의 연결 상태를 확인한다.

### 주요 어려움
- 파일을 수동으로 복사해 버전을 관리하면 변경 시점과 내용을 놓치기 쉽다.
- 고정 Excel 양식과 비정형 Markdown 문서를 각각 관리하면 메타데이터와 변경내역이 불일치할 수 있다.
- AI가 만든 내용은 검토 없이 공식 산출물로 확정하면 안 된다.

### 성공 기준
- 현재 프로젝트와 현재 Draft를 항상 식별할 수 있다.
- 버전 확정 전 변경 요약을 확인하고, 확정 후 두 시점의 메타데이터·본문 차이를 볼 수 있다.
- AI 대화 결과가 저장되기 전 검토 가능하고, 승인한 결과만 현재 프로젝트의 Draft가 된다.

## MVP 역할 경계
- 검토자·승인자·테스트 담당자 등은 향후 다중 계정/권한 모델에서 별도 페르소나로 추가한다.
- MVP에서는 P-ADMIN이 검토, 승인, 테스트 추적 관리까지 수행한다.
- 이 역할 경계는 FR-003의 임시 관리자 자동 로그인과 사용자 스토리 계획의 Q1 결정을 따른다.
